# AI 字幕核对

[English](ai-proofreading.en.md)

“字幕核对”用于检查已经成功转写的字幕。它不会替代 ASR，也不会自动改写全部字幕：LLM 只生成建议，用户明确选择后才创建新的字幕版本。

## 配置提供商

打开“设置 → AI LLM 提供商”，选择预设或 OpenAI-compatible：

- Ollama：本地服务，不需要接口密钥；必须填写已安装的模型名。
- MiniMax、Kimi、DeepSeek、Qwen、GLM：通常需要对应厂商密钥。
- OpenAI-compatible：填写兼容服务地址、模型和按服务要求提供的密钥。

点击“测试连接”检查地址、鉴权和模型。Docker 访问宿主机 Ollama 使用 `http://host.docker.internal:11434/v1`，不能使用容器自身的 `localhost`。

## 核对流程

1. 打开左侧“AI”。
2. 左侧只列出“已完成且有字幕版本”的任务。
3. 选择任务和 LLM 提供商，开始字幕核对。
4. 等待任务完成；离开后返回 AI 页面仍可查看当前运行。
5. 结果按原字幕顺序显示。需要修改的段落展开；连续正确段落分别折叠为“展开第 X-Y 段”。
6. 查看时间、原文、建议文本和修改原因，勾选要采纳的建议。
7. 点击“应用所选建议”。ASRbox 创建一个新版本并留在 AI 页面，可继续查看新字幕。

建议默认不选中。没有勾选时不能应用；未选择的建议不会修改字幕。已经应用或失效的建议不能重复覆盖新的版本。

## 结果与错误

- “没有发现需要修改的内容”：LLM 正常返回，且建议列表为空。
- 连接失败：服务地址不可达、Ollama 未启动、DNS 或网络故障。
- 鉴权失败：API key 错误、过期或权限不足。
- 模型错误：模型名不存在、未拉取或服务不支持。
- 上下文过长：字幕和提示超过所选模型限制，应换更大上下文模型或较短任务。
- 限流或服务端错误：等待后重试，或检查厂商状态和额度。
- 返回格式错误：LLM 没有返回可解析的结构化建议，可更换模型或重试。

只有第一种情况代表“核对完成且无需修改”，其余情况都不会冒充成功。LLM 故障不会改变原字幕，也不会让已经完成的转写失败。

## 隐私

请求包含字幕段落文字、段落编号和有限的相邻上下文，不包含音频、视频内容或本地文件路径。远程提供商会在第三方系统处理这些文字；使用前查看其隐私政策和保留规则。

LLM 密钥、运行记录和建议保存在本地数据库并会进入应用备份。诊断包不应包含密钥和建议正文。Ollama 只有在地址确实指向 loopback 或同一受控内网服务时才属于本地处理。

对于 128k 上下文模型，不能简单按“128000 / 30 个汉字”得到可靠段落数，因为提示、JSON、标点、时间戳、输出建议和 tokenizer 都占 token。ASRbox 会保留安全余量；长字幕应关注实际模型的输入与输出上限。
