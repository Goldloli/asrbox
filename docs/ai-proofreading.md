# AI 字幕核对与翻译

[English](ai-proofreading.en.md)

“字幕核对”用于检查已经成功转写的字幕。它不会替代 ASR，也不会自动改写全部字幕：LLM 只生成建议，用户明确选择后才创建新的字幕版本。

## 配置提供商

打开“设置 → AI LLM 提供商”，选择预设或 OpenAI-compatible：

- Ollama：本地服务，不需要接口密钥；必须填写已安装的模型名。
- MiniMax、Kimi、DeepSeek、Qwen、GLM：通常需要对应厂商密钥。
- OpenAI-compatible：填写兼容服务地址、模型和按服务要求提供的密钥。

点击“测试连接”检查地址、鉴权和模型。Docker 访问宿主机 Ollama 使用 `http://host.docker.internal:11434/v1`，不能使用容器自身的 `localhost`。

## 自定义平台的兼容设置

“测试连接”只验证基本响应。保存提供商后，点“测试翻译与校对”检查内置示例：最多 6 次请求、总计 3 分钟，可能产生平台费用，不会发送用户字幕或媒体。系统依次尝试严格结构、JSON 对象和仅提示词约束，只有两种业务示例都通过才提供“应用已验证设置”。测试不自动修改配置；应用时如果配置已变化，会要求重新测试。

编辑提供商，展开“翻译与校对兼容设置”：

| 设置 | 用途 |
| --- | --- |
| 参数协议 | 自动按预设或已知官方地址选择；自定义代理可明确选择 OpenAI、DeepSeek、Ollama、Qwen 或 GLM 协议，与模型名称无关 |
| 思考模式 | 自动、保留模型默认、请求关闭思考；纯思考模型不能强制关闭，请保留默认 |
| 输出约束 | 自动、JSON Schema、JSON 对象或仅提示词；不支持结构化参数的平台可使用仅提示词，再由 ASRbox 严格校验 |
| 响应方式 | JSON 完整返回或 SSE 流式返回；部分平台的思考模式要求流式返回 |

翻译和校对共享设置，每次请求均有 90 秒总时限与 1 MiB 响应上限，保活不能延长时限。流式只使用正文，不把推理片段写入字幕；截断、拒答、不完整结构会明确失败。真实字幕失败不会隐式尝试其他配置或自动重发。测试中的鉴权、限流、超时、连接等错误也立即停止，不继续试探。

能力测试是固定小样本验证，不代表平台一定执行了每个参数，也不能保证长任务速度、模型可用性、段落语义对齐或翻译质量。不支持 OpenAI Chat Completions 的 API 不能靠这些设置接入。没有兼容设置的旧配置会无损升级；修改兼容选项后可显式续译同一提供商、endpoint 和模型的未完成批次，已保存批次不重做。

## 核对流程

1. 打开左侧“AI”。
2. 左侧只列出“已完成且有字幕版本”的任务。
3. 选择任务和 LLM 提供商，开始字幕核对。
4. 等待任务完成；离开后返回 AI 页面仍可查看当前运行。
5. 结果按原字幕顺序显示。需要修改的段落展开；连续正确段落分别折叠为“展开第 X-Y 段”。
6. 查看时间、原文、建议文本和修改原因，勾选要采纳的建议。
7. 点击“应用所选建议”。ASRbox 创建一个新版本并留在 AI 页面，可继续查看新字幕。

建议默认不选中。没有勾选时不能应用；未选择的建议不会修改字幕。已经应用或失效的建议不能重复覆盖新的版本。

## 结果与错误

- “没有发现需要修改的内容”：LLM 正常返回，且建议列表为空。
- 连接失败：服务地址不可达、Ollama 未启动、DNS 或网络故障。
- 鉴权失败：API key 错误、过期或权限不足。
- 模型错误：模型名不存在、未拉取或服务不支持。
- 上下文过长：字幕和提示超过所选模型限制，应换更大上下文模型或较短任务。
- 限流或服务端错误：等待后重试，或检查厂商状态和额度。
- 返回格式错误：LLM 没有返回可解析的结构化建议，可更换模型或重试。

只有第一种情况代表“核对完成且无需修改”，其余情况都不会冒充成功。LLM 故障不会改变原字幕，也不会让已经完成的转写失败。

## 隐私

请求包含字幕段落文字、段落编号和有限的相邻上下文，不包含音频、视频内容或本地文件路径。远程提供商会在第三方系统处理这些文字；使用前查看其隐私政策和保留规则。

LLM 密钥、运行记录和建议保存在本地数据库并会进入应用备份。诊断包不应包含密钥和建议正文。Ollama 只有在地址确实指向 loopback 或同一受控内网服务时才属于本地处理。

对于 128k 上下文模型，不能简单按“128000 / 30 个汉字”得到可靠段落数，因为提示、JSON、标点、时间戳、输出建议和 tokenizer 都占 token。ASRbox 会保留安全余量；长字幕应关注实际模型的输入与输出上限。

## 多语言字幕翻译（未发布）

开发分支在“AI → 字幕翻译”提供独立翻译，复用上述提供商。它保留原文，不要求先校对；需要先校对时，选择校对生成的已保存版本作为来源。

1. 选择已完成任务及明确的原字幕版本。未保存的原文修改不会进入翻译。
2. 选择源语言和目标语言。源语言“自动”可处理混合语言；目标必须明确。常用选项包括简繁中文、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、俄语、阿拉伯语、印地语、泰语和越南语，也可输入 1–80 字符的自定义语言名称。固定同语种会被拒绝，简繁转换允许。
3. 查看提供商及本地／远端披露，点击“开始翻译”。每次只翻一种目标语言；其他语种可另建运行。打开页面、切换模式或刷新都不会自动发送请求。
4. 按已完成段落查看进度。可以离开页面再返回，或复制含 `mode=translation&run=…` 的链接定位运行。
5. 完成后逐段对照原译文，可搜索、播放原媒体、修改译文并一次保存为一个新版本。无媒体也可审阅和导出。来源更新后，旧译文仍绑定旧原文，不会混入新字幕。
6. 选择已保存译文版本，导出 TXT、SRT、VTT、ASS、JSON 或 Markdown。支持仅译文和双语；双语默认原文在前，可切换顺序。JSON 分别保存 `source_text` 和 `translated_text`。未保存的修改不进入导出。

翻译使用独立的运行和不可变版本，不改变原字幕、原字幕导出或校对结果的有效性。来源任务重新转写期间不能新建、续译或编辑译文，但历史仍可读取和导出。保存冲突会保留编辑草稿，需检查最新版本后再决定如何保存。

每个翻译请求最多等待 90 秒（包括提供商保活期间）；超时会显示错误并保留成功批次，可手动续译。界面显示本批等待时间，但只有完整结果通过校验才更新已保存进度。DeepSeek 预设使用 JSON 输出，V4 模型在翻译时关闭深度思考；这不改变校对或连接测试设置。模型仍可能漏段或输出错误，ASRbox 会拒绝不完整结果，不能用格式校验代替人工审阅。

每批最多 100 个目标段，目标与上下文合计最多 6,000 个 Unicode 字符；上下文最多前后各两段、合计 1,000 字。单段超过 6,000 字会在发送前拒绝。字幕需有唯一段号、非空文字和可导出的有效时间。字符数不是模型 token 数，仍可能遇到上下文或输出容量限制。

只有完整成功的批次会保存检查点，全部批次完成后才发布完整译文版本。取消会立即终止本地运行并丢弃迟到结果，但正在发送的请求可能仍执行至超时并被计费。失败、取消或重启中断后，需要手动“继续未完成批次”；不会自动付费重试。续译仅发送未成功批次，但远端已处理而本地未保存的批次仍可能再次计费。

续译会检查原提供商：地址、预设或模型改变后不能混接旧结果，应新建完整翻译；只轮换密钥可续译。删除提供商不删除已保存译文；删除原任务会同时删除其翻译。备份包含全部翻译历史和检查点。降级前先导出译文并备份数据库，旧版对新表的删除与恢复不受保证。

语言覆盖、语义准确性和术语一致性取决于所选模型。结构校验不能证明翻译正确；分享前请人工检查。首版不含术语库、配音、字幕烧录或自动时间轴调整。ASS 的字体和复杂文字显示由播放器决定，长双语内容不会被自动删减。

Ollama 翻译使用非思考模式及 JSON Schema 约束输出字段、段号和段数，以减少大型思考模型的等待及格式错误。请使用支持这些 OpenAI 兼容参数的 Ollama 版本；校对共享兼容设置，连接测试共享思考和传输设置，但不要求字幕输出格式。
