# ASRbox Open-Source MVP Hardening Design

## Goal

Prepare ASRbox for a public macOS Apple Silicon beta without adding unrelated product features. A release is ready when transcription never fabricates success, the loopback API is protected, untrusted uploads are bounded, dependencies and bundled binaries are auditable, release automation enforces the tested contract, and a clean desktop build completes the primary user flow.

## Release Positioning

The result remains a pre-1.0 public beta. macOS Apple Silicon is the only supported packaged target. Code signing, notarization, automatic updates, Windows, and Linux remain outside this branch; the documentation must state those limits prominently.

## Architecture

The existing React, FastAPI, SQLite, and Tauri structure remains intact. Security changes use one process-scoped bearer token generated by Tauri and passed to the sidecar through `ASRBOX_API_TOKEN`; this is local process authentication, not a user account system. Development without a configured token remains possible so contributors can run the Web UI and backend directly.

The backend validates transcription mode before persisting an upload. Local tasks require a catalogued model, while provider tasks require an existing enabled provider. The production placeholder transcription path is removed.

Uploads are streamed to disk with explicit per-file and per-batch limits. Limits are constants with conservative defaults suitable for long-form media, and oversized partial files are removed before returning HTTP 413.

## Ten Iterations

1. Remove placeholder transcription and validate local/provider task requests.
2. Add optional loopback bearer-token middleware and pass the token from Tauri to the frontend.
3. Remove unsafe CORS origins, add a desktop CSP, and narrow Tauri capabilities.
4. Enforce file-size, batch-count, and batch-total upload limits.
5. Upgrade Vite/esbuild dependencies and make dependency audit repeatable.
6. Separate Python runtime, test, and packaging requirements and generate a reproducible lock snapshot.
7. Add FFmpeg license text, source offer, build configuration, and checksum metadata to release resources.
8. Make release CI execute tests, binary smoke, version checks, and artifact verification.
9. Document beta limitations, local credential storage, provider data flow, installation, and uninstall behavior.
10. Add a browser smoke test for the critical shell and a single release-readiness command.

## Error Handling

Invalid backend, model, or provider selections return 422 before a task or upload is created. Missing or invalid API tokens return 401 without revealing the expected token. Oversized uploads return 413 and leave no partial media file. Dependency and license verification failures stop CI and release builds.

## Security Decisions

- The API token protects every endpoint except `/`, `/health`, and API documentation assets needed for diagnostics.
- CORS allows only the development origins and Tauri origins; opaque `null` origins are rejected.
- Provider credentials remain in the local SQLite database for this MVP. The UI never returns the full value, backups and documentation warn about local plaintext storage, and Keychain migration remains post-MVP work.
- The bundled GPLv3 FFmpeg build is treated as a separately licensed component. Release resources include the license and exact source/build metadata; ASRbox source remains MIT.

## Verification

Each behavior change follows red-green TDD with targeted pytest coverage. Completion requires backend tests, contract tests, TypeScript checks, Web build, Bun audit, Cargo checks/tests, frozen binary smoke, Playwright smoke, release-readiness script, and a Computer Use desktop walkthrough covering startup, navigation, backend health, and the transcription entry surface.

## Non-Goals

- User accounts, remote multi-user deployment, or cloud hosting hardening.
- Automatic updates, signing/notarization, or non-Apple-Silicon packages.
- Runtime plugin architecture or splitting every ASR engine into a separate download.
- Keychain migration in this branch.
