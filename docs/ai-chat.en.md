# AI Chat

[中文](ai-chat.md)

Chat is the third tab on the AI page, next to Subtitle proofreading and Subtitle translation. It reuses the providers configured under Settings → AI LLM providers and supports two modes: without a bound task, it answers app-usage questions from a built-in documentation knowledge base; with a task bound, it injects the task's current-version subtitles as context so you can ask about the subtitle content. Sessions and messages are stored in the local database and remain available across restarts.

## Asking questions

1. Open AI → Chat.
2. Click New chat, or simply type a question and send it (the first send creates a session automatically).
3. The sidebar lists previous chats; reopen one to continue, or delete a chat together with its messages. Deleting a chat never affects transcription tasks, subtitle versions, or provider configuration. The chat title is generated by truncating the first question.

Replies render incrementally, typewriter-style. Click Stop while a reply is generating to abort it; the partial content is kept and marked as stopped. Provider timeouts, rate limits, context-length failures, and invalid configurations are reported as distinct error types without affecting the existing chat or messages.

## Binding a transcript task

The Bound transcript selector at the top of a chat binds a completed transcription task to the session, or selects “No transcript (app Q&A only)”. When bound, each question includes the full text of the task's current subtitle version (the same notion of “current version” used by proofreading and translation); newer versions are picked up automatically. The binding persists with the session and can be changed or removed at any time.

If the bound subtitles and chat history exceed the model's usable context, ASRbox reports the context-length problem before sending instead of silently truncating the subtitles; unbind the task or switch to a model with a larger context.

## App Q&A knowledge base

ASRbox ships an offline knowledge base curated from the user documentation. Each question is matched locally by keyword retrieval, and matching passages are supplied as context. When nothing matches, the model still answers but states that the question is outside the built-in material instead of inventing features.

## Privacy boundary

Only the current chat's messages, the bound task's subtitle text, and matched knowledge-base passages are sent to the LLM. Other tasks' data, audio or files, provider credentials, and local file paths are never sent. Local-versus-remote classification, HTTPS enforcement, and credential masking match subtitle proofreading; a remote provider is third-party processing, so review its retention and privacy terms first. Each reply request has a 120-second total timeout and a 1 MiB response cap.
