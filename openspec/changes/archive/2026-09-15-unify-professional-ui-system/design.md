## 背景

动机与范围见 [proposal.md](./proposal.md)，可观察行为见 [specs/frontend-quality/spec.md](./specs/frontend-quality/spec.md)。本设计把用户选定的三张效果图解释为同一产品系统的三个视图：亮色首页、亮色任务详情，以及与首页同构的暗色主题，而不是三套相互独立的皮肤。

当前应用已经具备可复用的路由、状态和业务组件，但视觉职责分散：

- `app/src/components/AppShell.tsx` 同时装配顶栏、侧栏、主滚动区、持久播放器、移动导航和底部任务栏；顶栏与内容区目前更像独立工具条，缺少统一页面标题和内容画布边界。
- `app/src/components/Sidebar.tsx` 已支持展开与仅图标两种模式，`app/src/stores/uiStore.ts` 已持久化主题、密度、字体和侧边栏偏好，但新用户侧边栏默认为仅图标。
- `app/src/index.css` 已有语义变量和亮暗主题入口，不过页面渐变、半透明面板和大范围阴影被大量复用，导致嵌套卡片感与主题表面割裂。
- `app/src/components/surfaces.tsx` 提供 `Panel`、`PanelHeader`、`Toolbar`、`InspectorSection` 和 `DataRow` 等通用结构，但 `Panel` 默认同时承担边界、背景、圆角和阴影，页面只能通过重复嵌套面板表达层级。
- `app/src/routes/TranscribePage.tsx`、`TasksPage.tsx`、`AIPage.tsx`、`ModelsPage.tsx` 和 `SettingsPage.tsx` 已包含完整业务状态与交互。此次重构必须复用这些 producer、query、mutation、下载、编辑和错误处理逻辑，不改变后端 contract。
- 任务中心当前在任务页内打开详情。更新后的目标不是“列表页再弹出详情”，而是在同一任务中心中用左侧任务列表持续驱动中央播放器／转写结果和右侧任务状态。
- 默认模型已经由后端 ASR 设置表达；`SettingsPage.tsx` 可读写本地模型或提供商默认值。重构应复用这一权威来源，不在 UI store 中复制第二份默认模型。
- `uiStore.ts` 已本地持久化主题等纯界面偏好，适合增加强调色；强调色与成功、警告、错误等语义状态色必须保持独立。

## 目标 / 非目标

**目标：**

- 用一套稳定的语义 token 和结构组件覆盖亮色、暗色、桌面与窄屏，而不是为每个页面编写独立主题样式。
- 让应用壳体、首页、任务详情和其它全部页签形成明确的产品层级，同时保持既有状态管理、路由与功能 contract。
- 将视觉重构拆成可独立验证的壳体／基础组件、核心工作流、辅助页面和回归测试阶段，降低大范围同时改动的风险。
- 保留用户已有界面偏好；仅调整没有持久化偏好的新用户桌面导航默认值。
- 以 `0.3.0` 作为完成本 change 后的统一应用版本目标。

**非目标：**

- 不修改后端 API、事件、字幕版本、存储、模型下载、自动更新、桌面权限或发布流程。
- 不新增前端依赖，不重写现有数据获取和业务状态机，不引入新的路由或独立任务详情 URL。
- 不重新设计 ASRbox 品牌图标，不加入重型动效、玻璃拟态或装饰性插画，不追求与效果图逐像素复制；第三方品牌只使用正确、可追溯的官方标识。
- 不删除或弱化任何现有导出、编辑、版本、诊断、设置、模型管理和错误恢复能力。

## 决策

### 1. 先建立语义视觉层，再迁移页面

在 `app/src/index.css` 中保留现有变量入口并整理为四类语义 token：画布与表面、文字与边框、强调与语义状态、尺寸与动效。亮色使用温和的浅灰画布、白色主表面和深色正文；暗色使用深蓝黑画布、分层深色表面和浅色正文。组件只能消费语义变量，不直接根据主题写两套布局。

`uiStore.ts` 增加持久化 `accentColor`，允许 `orange`、`blue`、`purple`、`pink`、`red`、`green`、`cyan` 与 `gray`，默认 `orange`。应用根节点按该值映射 `--app-accent`、`--app-accent-soft`、`--app-accent-contrast` 和焦点颜色；成功、警告、错误、离线颜色保持固定。设置导入／导出包含该字段，未知值回退橙色。每种强调色分别为亮暗主题提供对比度合适的主色、柔和底色与前景色，不通过运行时任意 hex 输入生成样式。

减少全屏渐变、半透明叠层和大面积投影；层级主要依靠连续表面、1px 边界、间距、排版和少量近距离阴影。圆角使用有限层级：应用级表面最大、输入与按钮中等、状态标签最小。

选择该方式是因为现有主题入口和变量可以渐进迁移，且不会让亮暗主题分叉。备选方案是保留现有 CSS 并逐页覆盖，但它会继续累积页面特例，无法保证后续页签一致。

### 2. 应用壳体采用稳定导航加连续内容画布

`AppShell.tsx` 继续作为唯一壳体编排点，但把视觉职责收敛为稳定侧边导航、顶部命令区、可滚动内容画布和轻量底部任务状态。`Sidebar.tsx` 保留两种现有模式；`uiStore.ts` 只把没有旧持久化数据的新用户默认值改为展开，已有用户数据不迁移、不覆盖。窄屏仍使用 `MobileNav.tsx`，避免把桌面侧栏强塞入小屏。

全局搜索、本地运行状态和页面标题各自只有一个稳定位置。持久音频播放器和任务中心继续由壳体承载，但必须为主滚动区预留空间，避免覆盖最后一行操作。

选择稳定侧栏是为了让五个主路由在桌面端始终可识别，并与用户选定首页一致。备选方案是保留默认图标栏并用悬浮提示补偿，但这会继续呈现工具原型感，也降低新用户的导航可发现性。

### 3. 扩展共享表面组件，而不是建立第二套组件库

在现有 `surfaces.tsx` 与 `app/src/components/ui/` 上增加或整理少量组合结构：页面标题区、无阴影内容分区、分隔行列表、工作区侧栏、上下文检查器和统一反馈条。`Panel` 保留给真正独立的弹层或边界表面，并增加轻量变体；普通页面分区不再默认套用完整卡片外观。

现有 `weiui.tsx` 控件继续负责按钮、输入、选择、切换和可访问交互。通过 class 变体和语义 token 统一高度、焦点、禁用态及状态色，不创建名称相近但行为不同的新控件。

选择扩展现有组件是为了降低业务页面迁移量并保留测试选择器。备选方案是新建完整 design-system 目录并一次替换所有调用，这会扩大改动面且增加行为回归风险。

### 4. 首页使用“创建工作区 + 最近任务”两层结构

`TranscribePage.tsx` 的业务状态、文件导入、参数选择和启动 mutation 保持不变；视觉上将文件选择、模型、语言、更多设置和一个主要开始按钮组合为首页首要工作区。最近任务改为分隔行列表，状态、进度与常用操作在固定列中对齐；窄屏时每行重排为标题、元信息、状态和操作，不强制保留桌面表格列。

运行中和已完成结果仍在首页提供必要反馈。已完成结果遵守已有规格：结果下方只保留 SRT 与 TXT 快捷下载，不重新引入字幕预览或分段编辑。

选择两层结构是因为它同时服务“立即开始”和“回到最近工作”两个最高频目标。备选方案是将最近任务继续放入独立卡片网格，但长文件名、状态和批量浏览在网格中更难扫描。

### 5. 任务中心直接采用自适应三栏播放工作区

`TasksPage.tsx` 继续负责查询、筛选、选择任务和详情能力，不增加新路由或独立弹层。宽桌面中的任务中心直接形成三个区域：

1. 任务列表区：只显示任务筛选、状态分组和任务行，不显示导入按钮；选择任务后驱动其余两栏。
2. 主内容区：任务标题、音频播放器／波形、转写结果、可编辑分段和保存／放弃操作。
3. 任务状态区：处理状态、创建／完成时间、时长、大小、格式、导出，以及可折叠的标签备注、版本诊断、重试、清理与删除；不显示模型、语言、说话人识别等转写设置。

主内容区获得最大宽度和主要滚动焦点。中等宽度将任务列表压缩为可切换侧栏，并让任务状态区成为可关闭侧栏；窄屏按主内容、任务列表、任务状态顺序堆叠或通过可访问切换控件进入。任务标题、当前状态和返回列表控制保持稳定可达。

播放器、波形和转写结果通过同一 `currentTime` 与播放状态协调：媒体 `timeupdate` 或 seek 更新当前分段索引；分段播放入口定位到 `start_ms` 并播放；当前分段高亮并在跨段时滚入可见区域。高亮和自动滚动是派生视图状态，不写回分段、不创建字幕版本；用户正在文本输入时不得抢夺输入焦点。

选择常驻三栏是因为任务选择与审阅是同一连续工作流，也最接近用户选定参考图。备选方案是保留列表页加详情弹层，但它增加一次打开／关闭层级，且右栏容易继续混入创建任务时的转写设置。

### 6. AI、模型和设置沿用同一语法，但不强求同一版式

- `AIPage.tsx`：保留现有模式与任务选择，使用清晰的列表／编辑工作区；聊天、校对、翻译等模式共享页头、工具栏和反馈位置。
- `ModelsPage.tsx`：模型天梯继续默认折叠，展开后的排序和横向滚动限制在自身区域；模型目录、下载状态、设备能力和存储入口改用统一分隔行与状态组件。
- `SettingsPage.tsx` 与 `ProvidersPage.tsx`：保留当前页签和所有字段，通用页增加固定色板式强调色选择，页签下采用页面内分组、说明／控件双列或单列响应式布局；减少“卡片内再嵌卡片”，危险操作使用明确但克制的边界与状态色。

模型默认值使用后端 ASR 设置作为唯一权威来源。模型管理页“设为默认”调用现有设置更新能力并将后端切为本地；成功后使 settings、models 与首页依赖的 query 同时失效。设置页修改默认值沿用相同 producer。首页只在新建／重置草稿或尚未发生用户模型选择时吸收默认值，使用显式的“用户已覆盖”标记保护当前草稿。

已知提供商和模型的图标由一个集中映射按稳定 provider／model 标识选择。优先复用仓库已有官方资源；缺失时只 vendoring 许可与来源可记录的官方 SVG／PNG，并同步第三方 notice。自定义或未识别项使用现有通用图标。不得通过文字、emoji 或近似手绘图形冒充 Ollama、Qwen、OpenAI 标识。

统一的是层级、排版、间距、控件和反馈语言，而不是把每个业务页面压成相同三栏。这样既能形成品牌一致性，也保留各工作流最合适的信息密度。

### 7. 动效只表达状态与空间关系

沿用现有 CSS／组件能力，使用短时淡入、展开、侧栏位移和进度变化；尊重 `prefers-reduced-motion`。主题切换不对大面积背景做长动画，列表重排和任务状态更新不得造成内容跳动。

选择轻量动效是为了强化产品完成度而不增加依赖或影响长任务页面性能。备选方案是加入专用动效库，但当前没有足以证明依赖成本合理的复杂交互。

### 8. 验证以行为门禁加代表性视觉证据为准

复用现有 `test:frontend:unit`、`test:e2e:maintained` 与 `audit:frontend` 聚合入口。补充维护中的浏览器场景，覆盖五个主路由、任务详情、模型天梯和设置全部子页签；对亮／暗主题及桌面／390px 窄屏保留代表性截图或测试附件，并断言页面级横向溢出、主要控件可见性和键盘焦点。

测试优先使用稳定角色、名称和现有 `data-testid`，不绑定容易变化的装饰性 class。视觉证据用于人工比较所选方向，自动断言负责防止功能、可达性和布局边界回归；不在本 change 中引入新的像素快照服务。

### 9. 统一版本目标为 0.3.0

所有实现和回归通过后，使用现有 `npm run version:bump -- 0.3.0` 同步根 workspace、`app`、`web`、Tauri、后端及 lockfile 中由脚本维护的版本来源，再用 `npm run check:versions` 验证。版本提升安排在功能验证之后，避免开发中间态被误认为可发布；本 change 不执行 tag、发布或上传资产。

## 风险

- [全局 token 调整可能让未显式纳入的弹层或状态出现对比度回归] → 先建立语义映射和共享组件，再逐路由迁移；在亮暗主题中检查弹层、菜单、禁用、错误和离线状态。
- [任务详情三域布局可能在中等宽度压缩主内容] → 主区设置可收缩边界，侧区在明确断点切换为抽屉／折叠，不允许页面级横向滚动；用长文件名和长字幕验证。
- [播放联动的自动滚动可能干扰字幕编辑] → 仅在当前分段离开可视区域且用户未聚焦文本输入时滚动，高亮作为派生状态且绝不写入字幕版本。
- [可选强调色与语义状态色混淆] → 强调色只驱动品牌交互 token，成功、警告、错误和离线 token 固定；逐色验证亮暗主题对比度。
- [默认模型在多个页面各自缓存导致短暂不一致] → 所有入口复用同一设置 producer，并集中失效相关 query；不在 `uiStore` 复制默认模型。
- [第三方品牌图标存在许可或主题适配风险] → 只使用来源与许可可追溯的官方资源，记录 notice，并为单色／彩色资源分别验证亮暗背景。
- [一次覆盖全部页签导致 diff 大、问题难定位] → 按壳体与 token、首页与任务、AI 与模型、设置、回归五个阶段实施，每阶段完成聚焦检查后再继续。
- [重排 DOM 可能破坏现有自动化选择器或键盘顺序] → 优先保留可访问名称和稳定测试标识；结构调整同时更新维护中的场景，显式验证焦点顺序。
- [默认展开侧栏可能影响已有用户] → 仅修改 store 的无持久化初始值，不做版本迁移或覆盖已保存状态。
- [视觉效果图包含无法直接对应真实数据的装饰细节] → 以规格中的信息层级和连续表面为验收标准，真实功能状态、长文本和错误恢复优先于逐像素复制。

## 回滚

本变更不包含数据迁移、API 变更或不可逆状态。实施按阶段保持业务组件与数据调用边界，若某阶段出现阻断性回归，可回退该阶段的结构和样式改动，同时保留已经验证的共享 token。侧边栏默认值仅影响尚无持久化偏好的新用户；回滚时恢复旧初始值即可，已有用户偏好无需转换。任何回滚都不得撤销当前工作树中的自动更新修复或其它独立 change。
