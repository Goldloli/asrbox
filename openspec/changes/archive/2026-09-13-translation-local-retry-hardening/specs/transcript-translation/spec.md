## MODIFIED Requirements

### Requirement: 有界分批和真实进度

系统 SHALL 在发出首个请求前校验整份来源的批次可处理性，按确定的来源顺序以有界目标段数、字幕字符和邻段上下文分批。单批因提供商上下文容量不足、输出截断、请求超时或响应未通过完整性校验而失败时，系统 SHALL 将该批目标段对半拆分并按原顺序分别重试，递归至单段为止；拆分重试有界，不视为无限自动重试，子批不单独成为持久化检查点。进度 SHALL 来自已验证段落数，已验证批次 SHALL 持久化，完整结果 SHALL 仅在所有批次成功且所有来源段均被覆盖时原子发布。

#### Scenario: 来源超过单批容量
- **WHEN** 来源字幕超过单批目标数或文本限制
- **THEN** 系统分批执行并保存检查点，显示完成段数／总段数，不按等待时间虚增百分比

#### Scenario: 单个字幕段超过输入上限
- **WHEN** 来源存在不能独立装入一批的超长段落
- **THEN** 系统在发送任何文本前指出该段过长，不擅自拆 cue、截断文本或先运行部分批次

#### Scenario: 提供商上下文或输出容量不足
- **WHEN** 某批因提供商明确拒绝上下文长度，或输出被截断而未覆盖全部目标
- **THEN** 系统把该批目标段对半拆分、按原顺序重试，子批全部通过相同完整性校验后合并为该批检查点；单段仍失败时运行明确失败，区分上下文／响应完整性错误，保留此前有效检查点且不进行无限自动重试

#### Scenario: 提供商超时或响应覆盖不完整
- **WHEN** 某多段批因请求总时限耗尽（LLM_PROVIDER_TIMEOUT），或响应结构合法但未通过完整性校验（TRANSLATION_INVALID_RESPONSE，如重复或缺失目标段）而失败
- **THEN** 系统把该批目标段对半拆分、按原顺序重试，子批全部通过相同完整性校验后合并为该批检查点；单段仍失败时运行明确失败并保留原始错误码，保留此前有效检查点且不进行无限自动重试

### Requirement: 翻译请求的有界等待和结构化输出

翻译的每个提供商请求 SHALL 在总时限内完成，否则以 LLM_PROVIDER_TIMEOUT 失败；保活不得重置时限。总时限按提供商协议区分：本地 Ollama 原生协议请求 300 秒，其余协议请求 90 秒。界面 SHALL 展示实际等待及单批时限，完成进度仅来自有效检查点。翻译 SHALL 使用保存的共享兼容设置；默认 DeepSeek 请求 JSON（V4 关闭思考），默认 Ollama 请求经原生 Chat API 使用非思考模式、JSON Schema 输出约束和已配置上下文长度（默认 32768），其他协议按所选兼容设置执行。结构不合格、截断或拒答不得保存为成功；除上下文容量不足、输出截断、请求超时或响应未通过完整性校验触发的确定性对半拆分重试外，实际字幕请求不自动重发。

#### Scenario: 提供商持续保活但不完成响应
- **WHEN** 提供商持续发送保活或小片数据，单批到达总时限
- **THEN** 本地终止等待、释放请求资源，运行变为可显式续译的失败状态，后续排队任务可以继续

#### Scenario: DeepSeek V4 默认开启思考
- **WHEN** 用户选择 DeepSeek 预设的 V4 模型翻译字幕
- **THEN** 请求显式使用非思考和 JSON 输出模式，结果仍须覆盖所有目标段；校对共享兼容设置，连接测试不请求字幕结构约束

#### Scenario: 其他兼容提供商
- **WHEN** 用户使用除 DeepSeek／Ollama 外的预设或自定义 OpenAI 兼容服务翻译
- **THEN** 仅发送所选兼容协议对应的参数，请求受 90 秒总时限约束，不在格式失败后偷偷重发计费请求

#### Scenario: 本地 Ollama 思考模型翻译
- **WHEN** 用户使用 Ollama 预设进行字幕翻译
- **THEN** 请求经 Ollama 原生 Chat API 使用服务支持的非思考模式、JSON 输出约束和已配置上下文长度，请求受 300 秒总时限约束，保留完整性校验，校对共享兼容设置，连接测试不请求字幕结构约束

#### Scenario: 拆分重试只重发失败批次
- **WHEN** 某批触发确定性拆分重试
- **THEN** 仅重发该批拆分后的子批请求，已成功批次不重新发送，每个子批请求仍受其提供商协议对应的总时限约束
