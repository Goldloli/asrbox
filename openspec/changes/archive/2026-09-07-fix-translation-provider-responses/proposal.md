## 为什么

桌面人工测试的 DeepSeek V4 翻译在约 220 秒后因结构校验失败而终止。现有 HTTP timeout 仅限制读空闲时间，提供商保活可以让单批等待超过配置；翻译请求没有使用提供商支持的 JSON 输出约束，默认深度思考也增加了等待。

## 变更内容

- 为字幕翻译落实单批 90 秒总请求时限，保活数据不能无限延长等待，错误保留为可显式续译的终态。
- 对已知支持的 DeepSeek 翻译请求使用 JSON 输出及非思考模式，提示词提供结构示例；只接受完整 JSON 或单层 JSON 代码围栏中的完整 JSON，仍严格验证段 ID、类型和字段。
- 在翻译页面显示实际等待时间和时限说明，保留基于有效批次的进度，不伪造完成百分比。
- 回归验证真实保活慢响应、取消后迟到结果、结构有效性和提供商参数兼容性，重新生成桌面测试包。

## 能力（Capabilities）

### Modified Capabilities
- `transcript-translation`: 明确总等待时限、可接受的 JSON 展示包装和 DeepSeek 翻译参数。

## 影响

接触点：`backend/services/llm_providers.py`、`backend/services/translation.py`、相关测试、翻译面板及本地化、字幕翻译 spec 和 AI 使用指南。仅翻译的有界传输路径调整；校对和连接测试行为不变。复用现有运行时依赖，不修改 API 字段、数据库格式、源字幕或历史版本，不自动重试、不改用户提供商配置。验证使用隔离数据；凭据、原文和响应正文不写入日志或仓库。
