## MODIFIED Requirements

### Requirement: 全量且严格对齐的译文

翻译 SHALL 忠实表达来源，不把任务变成总结或补充说明。每个目标段 SHALL 恰好有一条非空译文；时间、顺序、段落边界和说话人 SHALL 由来源决定。系统 SHALL 校验结构化输出，可移除唯一且完整的外层 JSON／无语言代码围栏（围栏外不得有解释文字），随后执行相同的严格校验，拒绝无效 JSON、遗漏／未知／重复 ID、空文本、错误类型、额外结构字段及超限响应；来源内容中的指令 SHALL 只作为翻译数据处理。

#### Scenario: 提供商返回完整有效结果
- **WHEN** 全部目标段都收到有效译文
- **THEN** 系统按来源顺序保存完整结果，保留时间和说话人，且不把原 ASR confidence 当作翻译质量分数

#### Scenario: 某段译文恰好与原文相同
- **WHEN** 名称、符号或已经是目标语言的文本被模型原样返回
- **THEN** 该段可通过完整性校验，不因没有文字差异被丢弃或判为无结果

#### Scenario: 提供商漏段或改动结构
- **WHEN** 任一批次存在缺失段、重复段、未知段、空译文或不符合结构的输出
- **THEN** 该批次不成为有效检查点，运行明确失败，且不产生可导出的半成品或用原文冒充漏译

#### Scenario: JSON 仅带一层代码围栏
- **WHEN** 响应为完整 JSON 或仅被一层 json／无语言代码围栏包裹的完整 JSON
- **THEN** 系统校验完整内部对象；围栏外解释、嵌套围栏、多个对象和错误字段仍被拒绝

## ADDED Requirements

### Requirement: 翻译请求的有界等待和结构化输出

翻译的每个提供商请求 SHALL 在 90 秒总时限内完成，否则以 `LLM_PROVIDER_TIMEOUT` 失败；保活空行或持续小片数据不得重置总时限。等待期间界面 SHALL 展示实际已等待时间和单批时限说明，完成进度仍仅来自有效检查点。DeepSeek 预设的翻译请求 SHALL 启用 JSON 输出；支持切换的 V4 模型 SHALL 显式关闭思考模式，不更改用户配置和其他 LLM 功能。

#### Scenario: 提供商持续保活但不完成响应
- **WHEN** 提供商持续发送保活或小片数据，单批到达总时限
- **THEN** 本地终止等待、释放请求资源，运行变为可显式续译的失败状态，后续排队任务可以继续

#### Scenario: DeepSeek V4 默认开启思考
- **WHEN** 用户选择 DeepSeek 预设的 V4 模型翻译字幕
- **THEN** 请求显式使用非思考和 JSON 输出模式，结果仍须覆盖所有目标段；校对和连接测试不继承这些翻译专用参数

#### Scenario: 其他兼容提供商
- **WHEN** 用户使用其他预设或自定义 OpenAI 兼容服务翻译
- **THEN** 不发送 DeepSeek 专用参数，也不在格式失败后偷偷重发计费请求
