# Proposal: harden-translation-segment-alignment

## 为什么

`asrbox-mc1` 记录的失败模式今天仍然成立，且已定位到两个可修复的成因。2026-09-24 用真实管线 + 本机真实 Ollama 复核（合成跨词 fixture，未使用用户字幕）：23 次真实调用中 20 次可检出跨段漂移，全部以 `completed` 状态发布译文版本；其中 12 次挂着守卫探针的运行里，现行内容合理性启发式**一次都没有触发**。漂移形态包括末段重复、整段回卷复用开篇内容、退化填充（连续 8 段输出单字符 `a`）、以及跨 45+ 段复用同一内容。对照实验（同一 fixture 改为"逐字回显"任务）10/10 干净，说明失败发生在跨语言生成环节，不是映射环节。

随后追加的两轮对照实验（55 次真实运行，16/1600 与 64/6000 两个尺寸 × 4B 与 27B 两个模型）修正了对本 bug 的理解，也修正了"把批次改小就干净"这个最初假设：

- **批次大小不是漂移主因**：按本 change 的四条判据回查第一轮，16/1600 发布的版本仍带漂移 **7/11**（4B/40 段 1/5、4B/137 段 3/3、27B/40 段 2/2、27B/137 段 1/1），与 64/6000 的 8/11 相差无几。
- **固定开销接近零**：4B 0.041 s/请求、27B 2.195 s/请求，成本几乎线性于段数；`local64` 只在"段数刚好放得下"时快 7–10%，137 段上反而慢 2.06×（拆分重译的重复劳动）。
- **漂移的机制是边界**：判定只作用在单批响应上时，拆分边界与相邻已保存批次之间是结构性盲区（批内 180 条命中里有 11 条只能在完整版本上看见），因此**只把判据修好还不够，必须在发布前再判一次**。

两个成因都来自 2026-09-18 归档的 `align-ui-with-approved-renderings`：

1. **缓解措施被移除。** 该 change 把本地 Ollama 协议的初始批次上限从主 spec 要求的 16 段/1600 字符改成 64 段/6000 字符（`backend/services/translation.py:33-34`），而它没有任何 `transcript-translation` 的 spec delta。被违反的正是"小本地模型在更大批次下会出现滑窗式错位输出"这一条——也就是本 bug 唯一有实证的缓解措施。归档的 `translation-output-sanity-guard` 对照实验（19 段干净、38 段膨胀、76 段失败）说明小批次能减少出错，但**不是干净保证**：用第二轮标定后的判据回查第一轮那次唯一触发拆分的运行（请求形状 `[40,20,20]`），仍检出 1 处退化输出（整段译文只剩 `。`），而同一 fixture 未拆分的运行普遍检出 4–11 处。这也印证了本 change 的判断——修复点在"检测范围"，不在"批次大小"。
2. **检测按英文长度标定，对 CJK 失效，且不存在逐段对应信号。** `_content_misaligned`（`backend/services/translation.py:228-246`）要求相邻译文共享 ≥25 字符才进入判断；实测的中文重复串只有 3–14 字符，每次都在阈值处被跳过。膨胀分支要求译文 >2.2 倍源文，中译外实测比例 0.28–0.44，永不触发。代码中不存在任何 `source_i ↔ text_i` 的对应校验，因此"内容整体前移但不重复"在设计上就不可能被发现——这是已知限制而非本 change 的目标，但需要如实记录。

## 变更内容

- **恢复本地 Ollama 初始批次上限为 16 段/1600 字符**（`LOCAL_MAX_SEGMENTS`/`LOCAL_MAX_CHARACTERS`），使代码重新符合主 spec 已接受的 `有界分批和真实进度`；其余协议仍为 100 段/6000 字符，续译沿用持久化批次边界不变。依据是实验数据：检测生效后 `local64` 的请求数优势消失，而拿到零漂移结果的期望耗时比 `local16` 贵 2.0–2.8×；长字幕初始请求数由 3 增到 9 的固定开销代价在 27B/137 段上实测约 +11%。
- **重写内容合理性启发式为长度归一化判据，并在 55 次真实运行的语料上标定到零误报**：
  - 相邻译文归一化重叠：公共子串同时满足绝对下限与"占较短译文的比例"下限，且相对余量超过"其源文自身重叠 + 比例下限"（第一版的绝对余量 12 在语料上 0 命中，相对化后 32 命中且全部为真；重复台词行仍不误判）；
  - 批内重复渲染：同一译文文本出现在源文互不相同的多个段位，长度下限 4（覆盖末段重复、整段回卷、跨段复用）；
  - 退化填充：只在可确认的退化形态上命中（单字符、非目标文字的单字符重复、纯数字或转义填充、去边标点后为空），并限定源文长度，避免把中文合法两字词误判为退化；
  - 异常膨胀：保留整批式并新增逐条式（覆盖"一段吐出一大段元评论"的形态）。
  - 判据仍然**只驱动修复流程**，不改写模型返回的文本。
- **新增发布前作用域校验**：批内命中走既有确定性对半拆分（单段照旧直接接受）；全部批次组装成完整结果后、写版本之前再判一次，命中则对命中段做**有界一次**的定点重译（携带邻段上下文的单段目标）并复验，复验通过才发布，仍命中则以明确错误码失败并保留检查点。依据是实验：批内 180 条命中中有 11 条（8 个 run）**结构上只可能在完整版本上被看见**，跨拆分边界与跨批次的重复是当前 3/3 残余漂移的全部来源；2 个真实命中案例都在 1 轮定点重译内收敛。
- **补合成跨词 fixture 的确定性回归测试**：把实测的漂移形态与必须零误判的反例（重复台词行、高频短译文、合法两字词）固化为断言，并覆盖发布前作用域的两条路径（重译后发布、仍命中则失败不写版本），满足 `asrbox-mc1` 的验收条件"用自有合成 fixture 建立回归"。
- **新增可选真机回归测试**（`ASRBOX_RUN_REAL_MODELS=1`，默认跳过）：用同一合成 fixture 打真实本地提供商，断言每段译文对应当前源段。
- **如实记录残余限制**：纯位移（内容整体前移、无重复、无异常长度变化）无法被结构校验或本启发式检出；原样回显源文、模型元评论与占位符属另一类失败（实验称 R5 类），四条结构判据看不见它们，本 change 只记录并另开任务，不并入本次 diff。本 change 不引入语义级校验（回译、嵌入、LLM 判分），不改变归档设计中"不逐段保证翻译语义正确"的非目标，也不引入外部服务依赖。
- **验收口径（对应需求"速度不变、精度提高"）**：精度——落地后真机对照中，发布版本按本 change 四条判据零命中（现状基线：64/6000 盲跑 8/11 命中）；速度——长字幕（≥100 段）耗时不超过现状 1.5×、短字幕（≤40 段）绝对增量 ≤5 秒，且不慢于同等精度的大批次方案（`64/6000 + 双作用域`，实验基线比本方案贵 2.0–2.8×）。阈值取自实测最差格（长字幕 27B/137 段 1.47×，短字幕 4B/40 段 +2.3 秒），目标里不含"每一格都严格不慢"——那与必须新增的检查成本不相容，如实记录。
- **版本号提升到 0.3.4**（补丁号，当前 0.3.3）：走既有 `npm run version:bump -- 0.3.4`，同步版本文件、`Cargo.toml`、`backend/__init__.py`、`Dockerfile`、`compose.yaml`、`.env.example`、README、`docs/release.md`、`CHANGELOG.md` 与 `docs/releases/v0.3.4.md`，并补齐 CHANGELOG 与发布要点。版本号提升是发布动作，只改版本与发布材料；**不** commit、tag 或 publish。

## 能力（Capabilities）

### New Capabilities

（无）

### Modified Capabilities

- `transcript-translation`: `全量且严格对齐的译文` 的内容合理性启发式改为长度归一化判据。`有界分批和真实进度` 的行为也随之改变（本地批次上限回到 16 段/1600 字符），但该 requirement 的文本本就如此，本次只是实现追赶 spec，因此不产生 delta 块。

## 影响

- `backend/services/translation.py`：`LOCAL_MAX_SEGMENTS`/`LOCAL_MAX_CHARACTERS` 恢复为 16/1600；`_content_misaligned` 重写为可复用的归一化判据（相邻重叠、重复渲染、退化填充、整批与逐条膨胀），`OVERLAP_MIN_CHARS` 等常量随之调整；`execute_run` 在写版本前增加发布前作用域校验与有界定点重译，新增对应的失败错误码映射。
- `backend/tests/test_translation_execution.py`：新增漂移形态与零误判反例用例，以及发布前作用域的两条路径用例；`test_create_run_uses_local_batch_limits_for_ollama_only` 的批次形状断言随上限恢复更新。
- `backend/tests/test_translation_service.py`：替换断言 64/6000 的用例为 16/1600。
- `backend/real_tests/`：新增可选真机翻译回归（沿用 `ASRBOX_RUN_REAL_MODELS=1` 门禁与 `npm run test:backend:real-models`）。
- `app/src/components/transcript/TranslationPanel.tsx` 与 `app/src/lib/translationI18n.ts`：为新的 `TRANSLATION_ALIGNMENT_UNVERIFIED` 错误码增加映射分支与中英文可读文案（沿用既有"未发布版本 + 检查点保留 + 可重试"的表述模式）。
- `openspec/specs/transcript-translation/spec.md`：`全量且严格对齐的译文` 的启发式措辞与相关 scenario 更新。
- 版本与发布材料：`package.json`、`app/package.json`、`web/package.json`、`tauri/package.json`、`tauri/src-tauri/tauri.conf.json`、`tauri/src-tauri/Cargo.toml`、`backend/__init__.py`、`Dockerfile`、`compose.yaml`、`.env.example`、`README.md`、`README.en.md`、`docs/release.md`、`docs/releases/v0.3.4.md`、`CHANGELOG.md`，以及随 bump 重生成的 `bun.lock`／`Cargo.lock`。
- 无 API 路由、响应字段、事件或持久化结构变化；无新增依赖。
