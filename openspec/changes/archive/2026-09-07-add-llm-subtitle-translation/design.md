## 目标 / 非目标

目标是利用现有服务边界交付独立、可恢复、可审阅的字幕翻译，不让翻译更改原任务的结果和状态。保持字幕逐段映射，并能明确追溯“哪个原文版本、哪个模型、哪种目标语言、哪次人工修订”产生导出。

设计不引入通用 AI 工作流引擎、消息中间件、多用户系统、自动翻译 ASR 管线或新的语言检测依赖。不扩展原字幕结构编辑器来兼容混合语言轨道，不让用户把独立译文恢复覆盖为原字幕。首版产品非目标见 proposal。

## 决策

### 1. 交互入口和来源选择

- AI 页面增加“字幕核对／字幕翻译”标签。`/ai?task=<id>` 继续默认核对；新增受校验的 `mode=translation`，翻译历史可用 `run=<id>` 定位，刷新和任务切换保留操作类型。
- 新运行默认选择当前已保存的原字幕版本，也可手动选择原历史版本；请求必须携带明确的 `source_version_id`，不在后台默默改成另一版。未保存的原字幕修改不进入请求。
- 配置区域展示来源版本、源语言、目标语言、LLM 提供商及模型；不要求“先校对”。选择校对后的版本即可完成“先校对再翻译”。
- 首版一次翻一种目标语言；再次选择其他语言创建独立运行。历史标识来源版本、目标语言、模型、时间和状态，切换历史不偷偷更换语言。
- 已完成结果展示所有原文／译文行和时间码，允许搜索、播放对应原媒体、修改译文、保存修订和选择导出模式。无需逐条勾选“采纳”，因为译文不写回原字幕。未保存修订离开前使用项目既有未保存提示；导出只使用已保存版本。
- 桌面采用并列原译文；窄屏每段上下排列。文字区域使用独立双向文本隔离及自动书写方向，覆盖阿拉伯语等从右到左文本，不翻转时间码和按钮。
- 普通任务列表仍以已完成任务作为新建入口。明确选中的任务若因重新转写暂时不再符合条件，翻译详情保留只读历史入口，禁用新建／续译；不存在的任务或不匹配的 run 显示错误，不能回退成另一任务。无需给所有任务响应新增翻译标记字段。
- 复用 `audioStore`／`PersistentAudioPlayer` 时补充媒体加载后的定位和文件不可用状态，使翻译行播放能正确跳转并在缺失文件时继续文本审阅。

备选：在任务详情内再嵌入整套翻译面板会重复 AI 工作区；直接把校对的选择／应用按钮改成翻译会改变原交互。采用共用导航、独立面板。

### 2. 多语言设置与翻译规则

语言设置独立于 ASR 的语言列表。可搜索的常用选项包括简体中文 `zh-Hans`、繁体中文 `zh-Hant`、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、俄语、阿拉伯语、印地语、泰语和越南语，并提供“自定义语言”文本入口。列表用于便利选择，不作为 LLM 语言能力白名单。

typed language choice 区分 `auto`、`preset` 和 `custom`：源语言允许三者，目标只允许后两者。预设使用稳定语言代码，显示名来自受维护目录；自定义名称限 1–80 个字符并拒绝控制字符。客户端和服务端均校验；代码不是文件名或路径。明确相同的源／目标（代码相同或规范化自定义名称相同）提示更换目标；简繁两个预设视为不同。源语言自动模式覆盖混合语言，不额外发一次语言检测请求，也不把 ASR 的 `task.language` 当作已证实语言。

翻译系统提示固定为忠实、通顺、适合字幕阅读，保留事实、数字和专有名词，不增补解释或总结。源文本与上下文以 JSON 数据承载，字幕里的“忽略指令”等内容只作为待翻译文本。首版不加入自由 system prompt 编辑、术语库和风格参数；未来可在独立变更中扩展。

服务只校验结构完整性，不能证明译文语义正确或每种语言均受模型支持。原译文相同可能是人名、符号或原本就在目标语言，不能因此判为失败。界面说明质量取决于所选模型，并提供人工审阅。

### 3. 独立译文版本和最小持久化模型

使用三张新增表，不迁移或重分类原字幕版本：

| 表 | 主要内容 |
| --- | --- |
| `translation_runs` | UUID、task／source_version、源／目标语言、provider 引用及名称／endpoint／preset／模型快照（不含凭据）、状态、批次／段落进度、error_code、清理后错误、时间、执行 attempt、最新译文版本引用 |
| `translation_batches` | run、确定性序号和目标段 ID、状态、已验证译文 JSON；唯一 `(run_id, batch_index)`，作为恢复检查点 |
| `translation_versions` | run、版本序号、`translate`／`edit` 类型、parent_version、完整译文 segments JSON、时间；唯一 `(run_id, revision)` |

source_version 必须属于相同 task。译文 segment id 是来源快照内的 id，不是会随编辑重建的当前字幕数据库主键。时间、顺序和说话人从来源快照拷贝；原 ASR confidence 不作为翻译质量分数，译文响应不制造翻译置信度。

全部批次成功后，在一个事务中验证完整段 ID 集合、生成首份不可变 `translate` 版本并把运行标记为 completed；重复 worker 最终提交不能生成第二份首版。修改译文请求只提交全部 segment id／text 及 `base_version_id`；拒绝未知、重复、缺失 ID 和空译文。保存创建一份完整 `edit` 快照；无变化的保存返回原版本。版本基准过期返回 409，保存失败整体回滚。人工编辑完成后不修改批次检查点或历史快照。

来源后来被编辑、恢复或校对时，返回 `source_is_current=false` 并显示“基于较早原字幕版本”；保持其固定配对、导出和修订能力。译文永远不进入 `latest_version_id(task)`，不使校对结果 stale，不改变原文默认导出。原始转写重试中的任务禁止新建／续译和修订，既有历史仍可查看及导出。

备选：在原 `TranscriptVersion` 上增加 language／track 并重写所有 latest 查询，影响现有校对、编辑和恢复；另建只可变的译文列又无法追溯人工修改。采用翻译子资源及少量不可变快照。

### 4. 分批、校验和成本边界

翻译通常输出全文，不能照搬“最多 500 段／30,000 字”的稀疏校对批次。首版保守默认每批最多 100 个目标段、目标加上下文最多 6,000 个 Unicode 字符；上下文最多前后各两段、合计 1,000 字且计入总上限，超出时先裁减上下文。整段独自超过 6,000 字，在运行创建前明确报错并指出段号；不切开原 cue 或在发送后才发现最后一段不可处理。阈值是工程上限，不声称等价于模型 token 上限。

先对整份来源做预检（非空、段 ID 唯一、可导出的有效时间），然后固定批次成员关系。LLM 仅接收语言设置、目标 `{id,text}` 和有限邻段文本，返回 `translations: [{segment_id, text}]`。每个目标必须恰好一次出现；上下文不能被当作目标写回。拒绝无效 JSON、遗漏／额外／重复 ID、空文本、非字符串、额外结构字段及改变分段结构的输出。超长响应要有受控上限，翻译调用按需扩展现有 transport 的可选响应大小限制，保持校对默认调用行为。

每批请求复用现有 `chat_completion`，翻译设置 90 秒请求 timeout，worker 串行调用。收到有效结果后立即保存该批检查点，再推进 completed_segments；前端百分比来自完成段数，不由时间虚增。明确上下文超限、截断／不完整输出和模型配置错误，不自动反复调用或默默减少语义内容。

首版不做自动付费重试或自动递归拆批。显式续译只发送失败或尚未开始的批次，保留原来成功的检查点；如果某批远端已处理但结果尚未持久化时中断，重试仍可能再次计费，不能承诺跨第三方的 exactly-once。

### 5. 生命周期、取消、恢复与并发

状态流为 `queued → running → completed | failed | cancelled | interrupted`；失败／取消／中断可经用户操作再次 queued，attempt 增加。每任务最多一个 queued／running 翻译运行，使用部分唯一索引及锁内重新校验；其他目标运行可在终态后新建。同一任务的校对可独立进行，不设置跨两种 AI 操作的全局互斥。

后台使用独立单 worker 翻译队列，沿用现有 worker 异常隔离和自动补位模式，不把校对 service 泛化为工作流引擎。以下操作在 `task_transition_lock` 内短暂认领和提交：创建／续译、批次写入、最终完成、取消、人工修订、随任务删除。网络调用在锁外；回写前重新读取 task、run、状态和 attempt，已取消、已删除或旧 attempt 的响应全部丢弃。

取消立即记录为 cancelled、停止排后续批次，保留已验证检查点；正在等待的网络请求可能直到返回或既有 timeout 才释放 worker。界面不承诺远端已经撤单、不承诺退款；状态取消后迟到结果绝不可变为 completed。重试使用新的 attempt，不接受旧响应。全局单 worker 保证上一请求未结束时不会并发执行新 attempt。

重启把 queued／running 运行标为 interrupted，保留批次；不自动向第三方重发。worker 普通异常落失败并继续队列，线程级退出释放计数并补位。每次 attempt 实际开始时重新验证提供商可用性与身份快照，避免排队期间配置变化后使用错误模型；执行期间固定该次连接与模型配置。来源快照完整才允许续译；provider 缺失／禁用或 endpoint／preset／model 与运行快照不一致时禁止拼接续译，提示用当前配置新建完整翻译。允许仅轮换凭据后重试，凭据不写入运行快照。

删除原任务时在既有任务删除事务内按外键顺序清理翻译版本、批次和运行；已有 ASR 活动态删除限制保持不变。翻译后台迟到结果不能重新插入。删除 provider 保留结果身份快照，已完成译文仍可使用。

### 6. 接口与 typed consumer 接触点

下表是新增接口设计，不替代实施时的生成 OpenAPI。现有校对／原文导出接口保持兼容；所有新增 JSON 响应都声明 `response_model` 并在 contract 测试断言。

| 接口建议 | 语义 |
| --- | --- |
| `POST /tasks/{task_id}/translation-runs` | 输入 provider_id、source_version_id、source_language、target_language，校验后短认领并入队 |
| `GET /tasks/{task_id}/translation-runs` | 列出元数据历史，不携带所有版本的全文 |
| `GET /tasks/{task_id}/translation-runs/{run_id}` | 状态、真实进度、来源是否当前、最新版本 id、清理后错误与可执行动作；使用轮询，不新增 SSE 事件 |
| `POST …/{run_id}/cancel`、`POST …/{run_id}/retry` | 同一作用域内取消或显式续译；非法状态返回 409 |
| `GET …/{run_id}/versions`、`GET …/{run_id}/versions/{version_id}` | 修订元数据列表及指定版本的完整配对原文／译文 |
| `POST …/{run_id}/versions` | 基于 base_version_id 原子保存译文文本修订 |
| `GET …/{run_id}/versions/{version_id}/export/{fmt}` | 明确版本导出，mode 为 translated／bilingual，order 为 source-first／target-first |

typed response 明确暴露语言选择、source_version_id、source_is_current、provider_name、model_name、status、attempt、total/completed_batches、total/completed_segments、latest_translation_version_id、can_retry、can_edit、can_export、error_code 及时间。编辑／重试动作由后端结合当前状态计算，前端不读内部 options_json。路由中所有重型数据库组合、整份 JSON／导出渲染通过线程池执行，契合现有事件循环约束。

### 7. 单语／双语导出与字幕完整性

默认保留原任务导出入口；翻译面板提供明确的“导出译文／导出双语”。六种格式都从指定 translation_version 和绑定 source_version 组合，禁止临时拿任务当前字幕拼接。

- SRT／VTT：每个原 cue 一个相同时间区间；单语只有译文，双语在同一 cue 内按所选顺序分行。
- ASS：使用真正的 `\N` cue 内换行和受控文字转义，不能把换行拼成新的 Dialogue 行。字体仍由播放器环境决定，不承诺内嵌各语种字体。
- TXT／Markdown：按来源顺序输出译文或原译文配对；Markdown 有明确语言标识并正确缩进多行内容。
- JSON：包含 task_id、run_id、translation_version_id、source_version_id、语言设置、导出模式／顺序和逐段结构。双语分别保留 source_text／translated_text，不能只有不可拆分的拼接 text；不输出路径、provider secret 或内部 options。

渲染只作临时投影，不创建原字幕版本。所有输出使用 UTF-8；字幕文本中的换行、尖括号、ASS 标签和分隔符按格式转义，不能被解析为新增 cue、样式控制或时间行。过长译文／双语可给出可读性提示，但不自动截断、删词、合并 cue 或调整时间；需要手动精简。

下载文件名采用已清理的原名、task／run／version 标识、目标语言安全标识和模式；自定义语言名称不能成为路径。共享 Select 仅补充可选禁用状态、可访问名称及窄屏文本截断，供翻译选择器使用；旧调用保持默认行为。新渲染参数保持旧默认行为，并对原六种格式运行回归。

### 8. 隐私、迁移和文档

翻译沿用实际 endpoint 的本机／第三方披露、HTTPS／redirect／鉴权边界，显示字幕文本会被发送，不新增确认弹窗。不发送媒体、文件名、路径或时间戳；合法 HTTP Authorization 凭据仅用于认证，不放入 prompt。prompt／原响应／检查点／译文不能进入日志或诊断。

增量迁移创建三表、外键和唯一索引，已有任务／版本／校对数据不改写。翻译数据保存于现有 SQLite，自动随事务一致备份保留；恢复后中断运行沿用恢复规则。测试覆盖旧数据库连续初始化、迁移中断后重试、provider／任务删除和新备份恢复。旧版应用对新增表的删除行为不可靠，不能把“加法迁移”直接等同于无损降级。

实现收尾更新中英文 README、AI 指南（沿用 `docs/ai-proofreading*.md` 路径扩展内容）、隐私和 Docker 使用说明、CHANGELOG；不把尚未实现的能力写成当前已发布功能。

## 风险

- 小模型可能漏译、输出无效结构或难以保证低资源语言质量：严格校验完整性、完整对照审阅；人工多语验收，避免宣传所有语言质量一致。
- 逐段时间对齐可能限制跨句重组，批次之间术语未必一致：提供有限相邻上下文和一致的固定提示，首版接受人工修订；术语库另行设计。
- 字符上限不能准确代表所有 tokenizer：保守小批次与独立上下文错误，不把阈值包装成模型能力保证。
- 取消无法撤销已经提交的第三方请求：立即终止本地运行状态、丢弃迟到结果并明确费用边界。
- 同一来源反复翻译及保存完整修订会增加 SQLite 占用：首版随原任务统一管理和删除，不新增独立存储系统。
- 双语比原文占用更多画面，RTL／复杂文字渲染依赖播放器：测试 UTF-8、顺序、转义和 UI，不做自动改时长或字体打包。

## 回滚

部署前使用既有一致性备份保存数据库；迁移幂等且不改写原字幕。失败时保持原任务可用，修复迁移后重启。功能回退优先在包含新 schema 的版本中停用翻译入口和新运行，保留已有译文导出能力及数据；不随回退 drop 表。

必须降级旧二进制时，先导出要保留的译文并备份升级后的完整数据库，再使用升级前备份恢复旧版环境。升级后新增的其他原任务也需单独保留；不承诺旧二进制对新数据库进行删除／恢复操作的兼容性。OpenSpec 工具更新的旧技能备份位于本机临时目录，不进入仓库；CLI 必要时可单独退回 `1.6.0`，不作为产品版本回滚的一部分。

## 验证与实施顺序

按数据／contract、翻译执行与恢复、审阅与导出、集成收口分阶段实施，详细复选任务见 `tasks.md`。自动测试使用合成多语言字幕和 stub LLM，不访问真实第三方或下载模型。覆盖非英语源语言、非中文目标、简繁、混合语言、RTL、无空格语言、分段完整性、并发／取消迟到、来源变化、历史修订、六格式原文回归与双语导出。

聚焦检查后运行后端全套与 contract、前端单测／typecheck／build、维护 Playwright 和 `check:open-source`；新增前端场景接入既有聚合命令。桌面和 Docker Web 手动走通入口、历史、播放及下载；不涉及 ASR 推理、二进制或模型元数据，无需真实模型／长音频推理套件。若验收真实 LLM，使用合成短字幕显式运行本地 Ollama 和一个已授权远端提供商，并如实记录语言／模型和限制。
