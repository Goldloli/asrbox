# Design: translation-output-sanity-guard

## 背景

`backend/services/translation.py` 现行防线只有结构校验（`parse_translations`，translation.py:153）：ID 恰好覆盖、文本非空。真实用户在安装版（0.2.0 + translation-local-retry-hardening）上用 qwen3.5:9b 翻译 137 段字幕成功"完成"，但译文是滑窗式错位内容（安装版数据库 `translation_batches.translations_json` 实测：32/137 段译文 >3 倍源文，相邻译文共享大段文本）。

对照实验（`data/tmp/translation_overlap_repro.py`，真实提示词/数据/本机 Ollama）：

| 批大小 | 结果 |
| --- | --- |
| 76 段 / ~3000 字符 | 结构校验失败（30 秒）或滑窗内容通过校验（非确定） |
| 38 段 / ~3000 字符 | 结构通过，6 段 >3 倍膨胀，相邻重叠 27 字符，总量 1.9 倍源文 |
| 19 段 / ~1500 字符 | 干净：0 膨胀、0 重叠、总量 0.45 倍、7 秒 |
| 10 段 / ~800 字符 | 干净：3 秒 |

## 目标 / 非目标

目标：

- 初始批次按提供商协议区分上限，本地 Ollama 原生协议落在实证干净区间（16 段/1600 字符）。
- 内容合理性启发式（相邻重叠、总量膨胀）接入既有确定性拆分路径，把"结构合法但内容错位"的批次拆小，直到模型行为正常。
- 提示词明确要求目标隔离。

非目标：

- 不逐段保证翻译语义正确（启发式只捕捉集体性错位特征，不评判单段质量）。
- 不修改结构校验规则、检查点持久化模型、拆分递归上限语义。
- 不为其他协议调整批次上限（远端大模型未见该失败模式，且更大批次对其更高效）。
- 不做跨语言的长度比精确建模（阈值只识别极端异常）。

## 决策

### 1. 批次上限按协议区分

`make_batches(segments, *, local=False)`：local 时 `MAX_SEGMENTS_LOCAL=16` / `MAX_CHARACTERS_LOCAL=1600`，否则保持 `MAX_SEGMENTS=100` / `MAX_CHARACTERS=6000`。`create_run` 按 `llm_compatibility.resolved(provider).protocol == "ollama"` 决定。备选方案：

- 统一调小所有协议上限：远端大模型没有该问题，小批次只会增加请求数与成本，否决。
- 38 段作为本地上限：实验已证 38 段会膨胀，否决；16 段对 19 段实证干净区间留有安全余量，且 1600 字符上限对长段（单段可达数百字符）形成第二道约束。
- 拆分路径 `_sub_batch` 不需要上限逻辑：它已经在对半拆分，且 `saved_batches` 续译沿用持久化边界，批次形状稳定。

### 2. 内容合理性启发式

`parse_translations` 成功后、返回前检查（仅 ≥2 个目标时）：

- **相邻重叠**：任一相邻译文对的最长公共子串 ≥25 字符、且超出其源文对自身的公共子串 12 字符以上（`difflib.SequenceMatcher.find_longest_match`，仅相邻对，O(n) 对比较）。滑窗错位的直接特征；源文本身重复的行（重复台词）译文相同是合法的，用源文重叠余量排除；残余误判代价只是多一次拆分，结果仍正确。
- **总量膨胀**：整批译文总字符 > 2.2 倍源文总字符且超出部分 >200 字符。中英互译正常比例 0.4-2 倍；滑窗批次实测 1.9 倍但伴随重叠，膨胀检查主要兜底多语对下的极端情况（如 32 段集体 >3 倍时总量必然越界）。

触发后与 `TRANSLATION_INVALID_RESPONSE` 走同一 `split_and_retry()`；单段结果不再拆分直接接受（无法再拆，且单段+上下文的膨胀无法与合法扩展区分）。备选方案：

- 逐段长度比校验：碎片段（"ercome"→整句译文是合法翻译）与紧凑型语言对（中→英）会误伤，否决。
- 用 LLM 自检或嵌入相似度：引入额外调用/依赖，违反"后处理不得依赖外部服务"边界，否决。
- 校验失败直接报错而非拆分：错位的根因是批过大，拆分正是实证有效的修复，与既有确定性拆分语义一致。

### 3. 提示词目标隔离

`SYSTEM_PROMPT` 增加一句：每条译文必须只翻译对应目标段，不得重复上下文或其他目标段的内容，长度贴近源段。对小模型只是减弱诱因而非保证，真正的防线是 1+2。

## 风险

- 启发式误判（如大量重复台词的影片）→ 多余拆分，增加请求数但结果仍正确；单段总是接受，不会死循环。
- 模型在 16 段以下仍错位（更弱模型）→ 拆分路径继续对半到单段接受，与现状一致地暴露为质量问题而非崩溃。
- `difflib` 最坏复杂度：相邻对、单条译文 ≤1MB 响应约束内实际数百字符，成本可忽略。

## 回滚

恢复 `make_batches` 单一上限、移除内容检查与提示词新增句即可；批次边界在创建时持久化，已创建运行续译不受影响；无 schema/数据迁移。
