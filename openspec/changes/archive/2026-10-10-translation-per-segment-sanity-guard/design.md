# Design: translation-per-segment-sanity-guard

## 背景

- 现有判据全部位于 `backend/services/translation.py` 的纯函数 `alignment_hits`（:260-302），被两个作用域共享：批内 `_content_misaligned`（:313-322，触发 `split_and_retry` 确定性对半拆批）与发布前 `_repair_alignment`（:512-540，有界一次定点重译 + 复验，复验不过以 `TRANSLATION_ALIGNMENT_UNVERIFIED` 失败）。常量集中在 :36-52，注释记录了"55 次真实运行零误报"的校准基线。
- 污染形态来自 asrbox-mc1 对照实验（Beads asrbox-h7d）：回显（英文源文原样进译文槽）、元评论（「（注意：根据要求…）」「(Note: …)」）、占位符（「（无翻译）」）。三类都是**逐段 vs 源文**的信号，现有四条判据全是**段间集体特征**，结构性看不见。
- 主 spec `openspec/specs/transcript-translation/spec.md:46` 已声明该缺口；:52-54 的 scenario 确立误伤边界：名称、符号、已是目标语言的文本原样返回合法。
- 响应解析只校验 `isinstance(text, str) and text.strip()`（translation.py:197-199），任何非空字符串都通过结构层——污染精确漏在"结构解析"与"集体漂移特征"之间的空档。

## 目标

- 三类污染在批内与发布前两个作用域被检出，并复用既有修复语义（拆批重试、定点重译、失败保留检查点），不引入新错误码、不改 API/前端。
- 既有零误报边界保持：名称/符号短原样返回、已是目标语言的文本原样返回、正常台词括注、`[music]` 类符号标签、中文两字词、重复台词行。

## 非目标

- 不判定源/目标同主文字系统语言对（如英→西）上的回显：译文与源文同用拉丁字母时，无法在无语言识别依赖的前提下区分"未翻译回显"与"合法原样返回"，保守放行，维持 spec 既有边界。
- 不做单段语义质量评判、不做内容位移检测（spec 既有非目标，维持）。
- 不修改、不重写模型返回的文本（判据只驱动修复流程，spec :46 约束）。
- 不改翻译提示词与 JSON Schema。

## 决策

### 1. 判据实现位置：`alignment_hits` 内部新增逐段循环

三条判据都是"单段 (source, text) 对"的函数，直接加进 `alignment_hits` 的逐段循环（与退化填充/逐段膨胀并列），自动被两个作用域共享，调用方零结构改动。备选是在 `_content_misaligned` 与 `_repair_alignment` 各自实现——被否决：两处语义会漂移，且发布前复验必须重用同一判据函数。

### 2. 回显判据：归一化相等 + 长度下限 + 文字系统不兼容

三个条件缺一不可：

- **归一化相等**（`_normalized_text` 复用）：污染的定义性特征。
- **长度下限**（新常量 `ALIGNMENT_ECHO_MIN_CHARS = 20`，作用于归一化源文）：放行名称、符号、短标签。实验中的回显是整句（30+ 字符）。
- **文字系统不兼容**（译文主体字符集与目标语言主字符系统）：放行"已是目标语言的文本被原样返回"——该合法情形与回显共享"归一化相等"特征，只能靠文字系统区分。例：英→中目标，回显为拉丁字母整句 → 命中；中源内嵌长中文短语、目标中文、原样返回 → CJK 对 CJK → 放行。

文字系统映射为纯函数小表（Latin/Cyrillic/Greek/Arabic/Hebrew/Thai/Hangul/Kana/CJK），由运行绑定的 `target_language` 解析；`alignment_hits` 增加可选 `target_language` 参数（默认 `None` 时跳过回显判定，保持既有调用兼容）。目标语言经 `_content_misaligned` / `_repair_alignment` 从 `run.target_language` 传入——内部签名变化，不触 API/持久化。

备选：用"同批其他译文的主导文字系统"推断目标文字系统（无需传参）——被否决：整批全部回显时无参照，且换批后判定不稳定。

### 3. 元评论判据：括注 + 标记词锚定

命中条件：译文核心文本中存在括注（`（…）`/`(…)`），且括注内匹配翻译指令/说明标记模式（`注意[:：]`、`根据/按照(要求|指示|上下文)`、`以上是/以下是(译文|翻译)`、`Note[:：]`、`as requested`、`per (the/your) (request|instruction)`、`according to (the )?(request|instruction|prompt)`、`无法翻译|未能翻译` 等），且括注长度 ≥ 6 字符。台词括注「（笑）」「(laughs)」「（掌声）」不含标记词，不命中；括注长度下限进一步放行极短台词注释。

### 4. 占位符判据：整段即占位模式

命中条件：整段核心文本（去边标点后）完全匹配占位模式：`（无翻译）`、`(无翻译)`、`（未翻译）`、`（无法翻译）`、`（略）`、`(no translation)`、`(untranslated)`、`(not translated)`、`(skipped)`、`(omitted)`、`(N/A)`、`(none)`。只认**整段**匹配，不做子串匹配：来源符号标签（`[music]`）原样返回、正常含 none 词的译文都不受影响。`[music]` 不在词表且非括注形态，天然放行。

### 5. 复用既有修复语义，不做新分支

三条新判据的命中段走与既有判据完全相同的路径：批内拆批（多目标）、发布前定点重译 + 复验（复验重调 `alignment_hits`，新判据自动参与）、`ALIGNMENT_MAX_REPAIRS` 预算、非本地协议首跑不重发。echo 段定点重译后模型可能再次原样返回（它认为无需翻译）——按既有语义以 `TRANSLATION_ALIGNMENT_UNVERIFIED` 失败是合理终点，用户可修订译文（对照审阅支持文本修订）。

## 风险

- **回显判据假阳性残余**：跨文字系统、长度 ≥ 20 且模型本应原样保留的长专名整句（如长英文歌名在中文目标下）会被判回显并触发一次定点重译，复验仍同则运行失败。频率低（实验语料零例），且用户可在对照审阅中手工修订；记录为已知边界。
- **元评论标记词表**：词表过宽会误伤含「注：」的正常台词。以括注 + 翻译指向措辞双条件收紧，测试覆盖反例。
- **占位符词表**：`(N/A)`/`(none)` 理论上可能是极短源文的合法译文——源文本身为 "N/A" 时译文归一化相等但长度 < 20 不触回显；占位符判据以"整段匹配 + 括注形态"约束，裸 `N/A` 不带括号不命中。测试覆盖。

## 回滚

判据、常量、`target_language` 参数全部集中在 `backend/services/translation.py` 单文件内，回滚即还原该文件与测试；spec delta 随 change 一起 revert。无数据迁移、无 API 变化，检查点与已发布版本不受影响。
