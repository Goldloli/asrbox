## 背景

动机见 proposal.md。scripts/check-versions.mjs 已覆盖所有受维护版本源和版本化说明；.github/workflows/release.yml 从 docs/releases/<tag>.md 发布 Release 正文，并在 Docker 和 macOS 门禁、冻结烟测与资源校验通过后上传产物。当前 main 已包含本版本功能，独立设备展示改动不在发布范围。

## 目标 / 非目标

使应用界面、后端、桌面包和下载页面一致识别 0.1.6。说明基于已经接受的字幕翻译与平台兼容行为，保留 public beta、平台和模型质量边界。非目标及接触点见 proposal.md。

## 决策

遵循既有脚本和 Release workflow，不另造发布机制。由 Bun 与 Cargo 更新锁项，不更新其他依赖。以中文为主编写发布说明，并通过中英文 README／AI 指南提供入口，移除已发布功能的“开发分支未发布”表述。CHANGELOG 保留历史，把当前条目移入 0.1.6。

本 change 管理发布准备，完成本地验证后归档进发布提交；实际 main CI、标签、发布和资源验收由 Beads 发布任务跟踪，避免为了填写执行结果而移动已经发布的标签。

## 风险

本地门禁确认两个浏览器用例将当前版本写死为 0.1.5；同步其精确期望到 0.1.6，保留可见版本和后端版本断言，不改测试逻辑或弱化检查。

版本遗漏 → 版本门禁；产物与源码不一致 → 仅从通过 CI 的 main 标签构建并核对发布资源。远端构建失败 → 保留失败信息、诊断后安全重试，不发布不完整资产。模型生成质量不能以结构合法证明 → 说明需人工检查含义、人名和跨段对应，能力测试不是任意模型保证。

## 回滚

发布前恢复本次版本和说明变更可撤回准备；发布后不移动标签，若产物异常按 docs/release.md 标记受影响版本并发布后续补丁。保留应用数据，不操作用户数据库。
