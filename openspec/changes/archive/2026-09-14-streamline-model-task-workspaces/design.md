## 背景

参见 [proposal.md](./proposal.md) 的动机。当前三个界面的耦合点如下：

- `app/src/components/models/ModelLadder.tsx:25` 直接计算固定综合排序，并始终渲染完整表格和图例；`app/src/routes/ModelsPage.tsx:150` 无条件把它放在模型列表之前。
- `app/src/components/TranscriptViewer.tsx:23` 同时承担只读全文、音频、字幕预览和分段编辑，内容顺序为全文 → 音频 → 字幕 → 分段。
- `app/src/routes/TranscribePage.tsx:499` 在首页复用完整 `TranscriptViewer`，并通过 `app/src/routes/TranscribePage.tsx:561` 把音频播放器 portal 到右栏，导致首页也承担完整编辑器高度。
- `app/src/routes/TasksPage.tsx:539` 的任务详情是最大宽度 920px 的右侧抽屉；标签、备注、集合、输出和任务操作均排在 `app/src/routes/TasksPage.tsx:779` 的字幕页签之前，主要复核流程被推到首屏以后。
- 应用壳在 `app/src/components/AppShell.tsx:31` 负责主内容滚动并限制到 1680px；新增布局必须避免与顶部状态栏、移动导航、持久音频条和底部任务栏争用可视高度。

视觉目标以用户提供的图 2（1078×1076）为任务详情整体结构，以图 3（848×1304）为窄宽分段编辑细节；图 1（1814×1566）仅用于核对当前信息层级。参考图没有需要新增的位图资产：波形继续由真实音频生成，图标复用项目现有图标库，颜色、圆角、字体和控件继续使用现有 ASRbox token 与 `weiui` 组件。

## 目标 / 非目标

**目标：**

- 在不丢失现有模型事实、任务操作和字幕编辑能力的前提下，让三个页面各自突出一个主要任务。
- 让任务详情首屏在常用桌面窗口中同时看见音频、字幕预览和至少首个分段，并在 390px 窄屏保持可编辑。
- 让首页保留转写全文与音频复核，但把结果后续动作压缩为 SRT/TXT 两个快捷下载。
- 以可访问状态、稳定排序和可测试响应式边界实现折叠与重排。

**非目标：**

- 不修改任务、分段、版本、音频或导出 API，不新增服务端持久化字段。
- 不删除 TXT/SRT/VTT/ASS/JSON/Markdown 的完整导出能力；只缩减首页快捷入口。
- 不把标签、备注和集合从本地状态迁移到后端，也不重新设计任务列表筛选与批量操作。
- 不更改模型分档数据或能力来源。

## 决策

### 1. 模型天梯使用受控折叠与单一排序选择

`ModelLadder` 内维护 `expanded=false` 和排序维度状态。标题区整体提供可访问按钮，包含 `aria-expanded`、目标区域关联和方向图标；折叠时不渲染表格与图例。展开后在表格上方放置一个带标签的 `Select`，选项为综合、名称、速度、准确率、语言、GPU、CPU、时间轴、说话人分离和下载状态。

所有比较器固定为最有用项优先：等级 S→C、布尔能力 true→false、下载完成→未下载，名称按当前可读名称升序；最后统一以模型名称作稳定回退。行数据与比较器使用 memo，状态刷新不会产生不确定跳动。

备选方案是让每个表头循环升降序。它的桌面操作直接，但窄屏表头在横向滚动中不易发现，也增加方向状态与无障碍提示；单一选择器更符合“选择各个选项进行排序”且在所有尺寸一致。

### 2. `TranscriptViewer` 拆分为首页摘要与任务详情两种呈现模式

保留一个共享字幕工作区组件，但明确两种模式，复用全文、音频、导出和分段草稿逻辑而不复制状态：

- `summary`：用于首页，继续显示任务标题、状态、进度、只读全文和既有右栏音频 portal；结果下方仅显示 SRT、TXT 两个下载按钮，不构造字幕预览与分段编辑 DOM。
- `detail`：用于任务详情，按音频播放器 → 字幕预览 → 分段编辑排序；全文搜索／复制与保存／放弃操作放入贴近编辑区的工具栏。任务详情外层已有标题时，组件使用嵌入式样式，避免重复 Panel 标题和重复最小视口高度。

首页与任务页共享小型导出按钮组件或导出回调契约；路由继续负责下载反馈和任务页的最近导出记录。这样不触碰导出 API，也不会把任务页本地管理状态塞入通用字幕组件。

备选方案是为首页复制一个精简字幕组件。它短期改动较少，但全文、音频、下载错误处理和文案会出现两套实现，因此不采用。

### 3. 任务详情采用一个视口级抽屉、内容优先主区和折叠的次要管理区

抽屉继续覆盖当前页面，不新增路由。桌面宽度从当前 920px 调整为 `min(1080px, calc(100vw - 96px))`，窄屏使用 100% 宽度；高度始终为可用动态视口，结构保持固定／粘性标题和唯一的外层内容滚动区。正文先呈现进度／错误（若有）及 `detail` 字幕工作区，再呈现折叠的“任务信息与操作”区域，里面保留元数据、标签、备注、集合、完整格式导出、最近导出、AI 入口、重试／清理／删除和时间线／版本／诊断。

音频波形保持约 96px 高；字幕预览和分段列表使用可视高度上限但不设置不可达的固定高度。分段行使用 `clamp` 的时间列加弹性文本列，在 320–390px 仍保留参考图的左右关系；按钮和工具栏允许换行，所有横向滚动限制在明确的表格或预览内部。

备选方案是彻底删除次要任务信息，能更接近截图裁切范围但会造成功能回退；将其折叠后置既保留能力，也能让首屏符合图 2 的内容层级。

### 4. 保持既有视觉系统，不生成新装饰资产

继续使用项目现有字体栈、黄色强调色、绿色状态色、面板边框、圆角和 `lucide-react` 图标。波形使用 `WaveformAudioPlayer` 的真实音频 canvas，不使用截图或占位图复刻。最终按相同视口和状态捕获参考与实现，执行设计 QA；桌面检查 1280×820 与 1440×900，窄屏检查 390×844，并覆盖展开天梯、完成任务首页和任务详情三种状态。

## 风险

- [共享组件模式分支使字幕状态复杂] → 让草稿、搜索、音频状态仍只有一份来源，按模式只控制区块呈现与顺序；用首页无编辑器和任务详情可保存两组 E2E 约束。
- [任务详情后置次要能力后不易发现] → 使用明确命名的折叠入口并保留错误／失败状态的诊断提示；危险操作不混入主要编辑工具栏。
- [真实音频在测试或 Web 环境不可解码] → 保留现有波形失败状态和重新关联路径；布局测试不把成功解码作为详情可用的前提。
- [宽屏抽屉扩大后遮住任务列表] → 只在打开详情时使用覆盖层，最大 1080px 且保留桌面侧边留白；关闭按钮始终可见。
- [首页只露出两种格式被误解为格式能力减少] → 快捷区明确使用下载语义，任务详情仍呈现完整格式，并在 E2E 中同时验证两处职责。

## 回滚

该变更没有数据迁移。若出现布局或交互回归，可恢复 `ModelLadder` 的默认展开、让首页回到完整模式，并把任务详情内容放回原页签；后端任务、版本和导出数据无需回滚。实现期间保持自动更新变更目录与相关代码不动，两个 change 可独立撤销或归档。
