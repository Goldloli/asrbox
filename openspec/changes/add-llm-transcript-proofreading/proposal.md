## Why

ASRbox 已经能够保存和编辑已完成的字幕，但目前用户仍需手动查找并修正识别错误。首个 LLM 校对流程需要提供保守、可审阅的文本修改建议，同时不能让转写是否成功、现有字幕版本、导出能力或本地优先的隐私承诺依赖任何 LLM 服务。

## What Changes

- 新增独立的 LLM 提供商管理，内置 MiniMax、Kimi、DeepSeek、Qwen、GLM 和本地 Ollama 预设，并支持自定义 OpenAI-compatible 提供商。
- 在桌面侧栏和移动端导航新增独立的 `AI` 工作区，首版只提供“字幕核对”；任务详情仅为成功字幕保留轻量跳转入口，现有任务面板保持不变。
- 在设置页新增一级 `AI LLM提供商` tab，与 ASR 在线提供商配置分离，并提供保存后自动测试及随时可用的连接测试操作。
- 支持针对已完成字幕版本创建异步校对任务。校对只发送字幕分段文本及有限的文本上下文，绝不发送音频或本地文件路径。
- 按字幕原顺序展示核对结果：修改建议显示原文、建议文本、差异和原因；连续的无建议字幕区间分别折叠。所有建议默认不选中，只有用户明确选择后才能应用。
- 以原子事务应用用户选中的建议，只修改文本，并创建新的不可变 `proofread` 字幕版本。分段时间、说话人、置信度和边界保持不变。
- 持久化校对任务和建议以便稍后审阅；每个任务绑定其来源版本，并在当前字幕版本发生变化后拒绝应用旧建议。
- 将 LLM 错误、异常响应、进程中断和提供商不可用与已完成字幕及所有现有版本隔离。
- 扩展隐私说明和备份行为，覆盖 LLM endpoint、字幕文本传输、本地明文凭据存储以及持久化校对数据。

## Capabilities

### New Capabilities
- `llm-provider-management`：配置、校验、脱敏展示、披露并使用独立的 OpenAI-compatible LLM 提供商及受支持的厂商预设。
- `transcript-proofreading`：创建、审阅、持久化、失效并选择性应用保守的分段级 LLM 字幕校对建议。

### Modified Capabilities
- `transcript-editing-versioning`：把已应用的校对选择记录为新的不可变字幕版本，同时保留历史版本和恢复行为。
- `storage-privacy-recovery`：区分本地 Ollama 与第三方 LLM 数据传输，并把 LLM 凭据和持久化校对数据纳入已记录的本地数据库与备份边界。

## Impact

- 后端：新增持久化的 LLM 提供商、校对任务和校对建议记录，以及数据库迁移、提供商客户端、隔离的 worker 生命周期、任务删除和启动恢复集成。
- API：新增带类型的 LLM 提供商与字幕校对路由和模型，并更新生成的 OpenAPI 与 contract 测试。
- 前端：新增独立 AI 路由、桌面和移动导航、可核对任务选择、响应式校对审阅工作区、任务详情轻入口，以及一级 LLM 提供商设置 tab。
- 文档：更新隐私说明和面向用户的提供商披露。
- 依赖：不计划新增运行时依赖；OpenAI-compatible HTTP 请求复用现有 `requests` 依赖。
- 现有转写路由、任务状态、ASR 提供商配置、事件类型、导出格式和字幕恢复语义保持向后兼容。
